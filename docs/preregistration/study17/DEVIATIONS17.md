## 1. 구현 해석 (2단계, 개발 실행 전에 코드로 정함)
원문과 답변이 정하지 않은 세부를 아래처럼 구현했다. 바꾸려면 Kyle이 정하고, 그 부분만 다시 돌린다.
1. **손절 표시 순서:** 같은 결정 시점에 기한, E1, 손절이 겹치면 기한 → E1 → 손절 순으로 이름을 붙인다.
   - 셋 다 같은 가격(그 막대 끝 호가)과 같은 D1 계산이라 비용은 같다. 차이는 "손절 발동 비율"을 셀 때뿐이다.
2. **손절 확인의 호가 0:** 결정 시점의 bid나 ask가 0 이하이면 그 시점은 손절을 확인하지 않고 센다. 개발에서는 0회였다.
3. **A* 동률 판정:** 최저 평균과의 차이가 0.02¢ 이하이면 동률로 본다. 그중 p95가 가장 낮은 후보를 고르고, p95가 정확히 같으면 규칙 수가 적은 쪽, 그래도 같으면 번호가 작은 쪽을 고른다.
   - 규칙 수는 C0 1, C1 0, C2 2, C3 2, C4 2, C5 3으로 셌다(SPEC17_QUESTIONS 16, 답 없음).
   - 이번 선택에서는 쓰이지 않았다. 2위 C2와 0.034¢ 차이로, 동률이 없었다.
4. **Holm에서 가설이 하나일 때(A* = C0):** α 0.05로 둔다(SPEC17_QUESTIONS 17 마지막 질문, 답 없음). A* = C3이라 쓰이지 않는다.
5. **보조 결과:** 판정은 단측 p와 단측 97.5% 상한이다.
   - 양측 95% CI도 같은 부트스트랩으로 함께 적는다.
   - 3 × 3 칸은 칸마다 그 칸의 거래일 수로 부트스트랩 색인을 만든다(16-E 방식, seed 17).
